NeMo Relay memory separates two ways of using memory:

- **Automatic reference memory** installs a native in-memory component around
  ordinary managed LLM calls. It retrieves, injects, and writes memory without
  adding memory tools to the agent's reasoning loop.
- **External provider adapters** implement the asynchronous `MemoryProvider`
  contract in application or integration repositories. Provider SDKs do not
  enter the default Relay package closure.

The provider contract always partitions data by `tenant_id` and `subject_id`.
Optional session and agent identity can narrow a search, but cannot broaden it.
Records retain original content, event and ingestion timestamps, provenance,
metadata, and stable Relay identity across providers.

## Automatic Reference Mode

Install the zero-service component once, then call the normal managed LLM API.
The agent does not call search or store.

```python
from nemo_relay import memory

component = memory.InMemoryAutomaticMemory(
    memory.AutomaticMemoryConfig(
        namespace=memory.MemoryNamespace("demo", "alex"),
    )
).install()

try:
    # Use nemo_relay.llm.execute(...) as usual.
    ...
finally:
    await component.shutdown()
```

The automatic component emits separate references-only evidence for retrieved,
injected, written, and maintenance facts. It does not expose raw memory content
in evidence by default, and it does not claim that retrieval caused an answer
unless a later citation or evaluator establishes that relationship.

## Direct Provider Mode

Use an external adapter when an application or worker owns provider calls. The
adapter implements `MemoryProvider`, constructs its vendor client from
application-owned configuration, and receives the same validated search and
store DTOs. Its import path and optional dependencies belong to that integration
repository rather than `nemo-relay`.

Direct Python providers cannot currently be passed to
`InMemoryAutomaticMemory`. That component owns a native Rust reference
provider. A future bridge can connect the same Python contract to automatic
execution without changing adapter semantics.

Refer to [Memory Providers](/memory/providers) for the external adapter
boundary and current limitations. Refer to
[Memory Runtime Design and Status](/contribute/memory-runtime-design) for the
runtime architecture, lifecycle evidence, background queue, maintenance
interface, and prompt-cache boundary.
