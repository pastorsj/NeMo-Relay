The `nemo-relay-node/hivemind` profile connects NeMo Relay lifecycle events to
[Activeloop Hivemind](https://github.com/activeloopai/hivemind). Hivemind is an
organizational-learning system: it captures agent traces in Deeplake, creates
session summaries asynchronously, and mines reusable skills from repeated
work. It is not an implementation of Relay's generic `MemoryProvider`.

Relay validates this bridge against Hivemind `0.7.113`. Hivemind is installed
and authenticated independently, so a normal `nemo-relay-node` installation
does not acquire Hivemind, Deeplake, embedding, or model dependencies.

## Capabilities

```javascript
const { hivemindCapabilities } = require('nemo-relay-node/hivemind');

console.log(hivemindCapabilities());
// {
//   traceCapture: true, search: true, summaries: true, skills: true,
//   store: false, update: false, delete: false, vectorCrud: false
// }
```

The distinction is intentional:

- **Trace** means a captured sequence of Relay lifecycle events.
- **Summary** means a Hivemind-generated wiki artifact derived from a source
  session.
- **Skill** means a Hivemind-generated `SKILL.md` artifact derived from one or
  more source sessions.
- None of these operations is equivalent to arbitrary fact store, update,
  delete, or vector CRUD.

Search results preserve Hivemind order as `rank`. The bridge does not invent a
numeric relevance score because the current Hivemind MCP search response does
not provide one.

## Install Hivemind

Follow Hivemind's current installation and authentication instructions. For a
Codex-oriented local installation, upstream currently documents:

```bash
npm install -g @deeplake/hivemind
hivemind codex install
hivemind status
```

The default bridge expects installed Codex hooks at
`~/.codex/hivemind/bundle/capture.js` and `stop.js`, plus the shared read-only
MCP server at `~/.hivemind/mcp/server.js`. Pass explicit paths to
`InstalledHivemindClient` if your deployment owns a different layout.

## Capture a Relay Session

```javascript
const relay = require('nemo-relay-node');
const {
  HivemindOrganizationalMemory,
  InstalledHivemindClient,
} = require('nemo-relay-node/hivemind');

const agentScope = relay.pushScope(
  'migration-run-17',
  relay.ScopeType.Agent,
  null,
  null,
);
const organizationalMemory = new HivemindOrganizationalMemory({
  client: new InstalledHivemindClient({
    skillRoots: [`${process.cwd()}/.claude/skills`],
  }),
  namespace: {
    tenantId: 'acme',
    subjectId: 'platform-team',
    sessionId: 'migration-run-17',
    agentId: 'migration-agent',
  },
  capturePolicy: {
    consent: 'explicit',
    captureContent: true,
    categories: ['llm', 'tool', 'memory'],
    redact(event) {
      // Apply application-specific secret or PII redaction here.
      return event;
    },
  },
  model: 'deployment-model-name',
  queueCapacity: 1024,
}).install({ scope: agentScope });

try {
  // This is an ordinary managed LLM call. The agent does not call a Hivemind
  // search or write tool in its reasoning loop.
  const response = await relay.llmCallExecuteAsync(
    'migration-planner',
    {
      headers: {},
      content: { prompt: 'Plan a backward-compatible schema migration.' },
    },
    async () => ({
      answer: 'Add the replacement field, backfill it, and then remove the old field.',
    }),
    null,
    null,
    null,
    null,
    'deployment-model-name',
  );

  await organizationalMemory.finish({
    assistantMessage: response.answer,
  });
  await organizationalMemory.flush();
} finally {
  await organizationalMemory.shutdown();
  relay.popScope(agentScope);
}
```

`finish()` invokes Hivemind's stop lifecycle. Successful return means the hook
accepted the event. Hivemind summary and skill workers remain asynchronous, so
it does not prove that a derived artifact is already searchable. Applications
that require read-after-derivation behavior should poll with a bounded timeout
or consume a deployment-owned completion signal.

The subscriber captures only configured categories. It serializes accepted
work outside the managed-call path and exposes failures through `status`,
`flush()`, and `shutdown()`. `shutdown()` deregisters and drains accepted work;
it does not implicitly finish a session.

Use a scope-local installation for each concurrently active agent identity, as
shown above. A global installation observes the process-wide event stream and
is appropriate only when that process has one explicit Relay identity. The
capture queue is bounded by `queueCapacity`; overflow is rejected and visible
through `status.rejected` and `flush()` instead of accumulating unbounded work.

## Search from Another Agent

```javascript
const result = await organizationalMemory.search({
  query: 'safe schema migration',
  kinds: ['summary', 'skill'],
  limit: 5,
});

for (const artifact of result.artifacts) {
  console.log({
    kind: artifact.kind,
    reference: artifact.reference,
    sourceSessions: artifact.provenance.sourceSessionIds,
    derivation: artifact.provenance.derivation,
  });
}
```

This is the organizational-learning flow:

1. Agent A performs ordinary Relay-managed work.
2. The installed profile captures its consented lifecycle events under an
   opaque Hivemind session key.
3. Hivemind asynchronously derives a summary or skill that names its source
   session.
4. Agent B searches the same authorized workspace and discovers that artifact.

The artifact proves derivation and discovery. It does not prove that Agent B
used the artifact in an answer. Answer-use attribution remains a separate
evaluator or citation fact.

## Privacy and Isolation

<Warning>
Hivemind captures full prompts, tool inputs, tool outputs, assistant responses,
and related activity. Upstream documents that members of the selected Deeplake
workspace can read captured data. Configure the workspace as the organizational
security boundary and obtain consent before enabling this profile.
</Warning>

Relay refuses to construct the profile unless `consent` is `explicit` and
`captureContent` is `true`. It hashes tenant, subject, session, and agent into a
versioned opaque Hivemind session key, so raw Relay identifiers do not appear in
Hivemind paths. This hashing is correlation hygiene, not access control and not
a replacement for separate Hivemind workspaces.

Use `capturePolicy.redact` to remove secrets, credentials, personal data, or
other content your organization does not permit Hivemind to retain. The Relay
bridge explicitly enables capture only after it validates this policy. For an
upstream read-only Hivemind process, do not install
`HivemindOrganizationalMemory`; use a deployment-owned read client instead.
Retention, deletion, legal hold, membership, and workspace administration
remain Hivemind/Deeplake operational responsibilities because this Relay
profile does not claim equivalent CRUD.

## Transport and Compatibility

The default bridge uses Hivemind's installed process boundaries rather than
private JavaScript modules:

- Codex capture and stop hooks accept structured lifecycle JSON on standard
  input.
- The read-only MCP server exposes trace and summary search.
- Configured local skill roots expose generated `SKILL.md` files and their
  `source_sessions` frontmatter.

Injected clients can implement the same `capture`, `finish`, and `search`
protocol for a container or service deployment. Revalidate this bridge when a
Hivemind upgrade changes installed paths, hook input, MCP tools, or result
format. Default Relay package metadata deliberately contains no Hivemind
dependency.
